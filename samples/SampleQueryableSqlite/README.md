# SampleQueryableSqlite

End-to-end demonstration of an EF-lite-style ORM built on top of the Phase B
expression-tree capture (#196) and the runtime stage-introspection helper (#200).
The C# side declares a domain (`Product`), an adapter contract
(`IProductRepository`), and a thin demo class (`ProductDemo`) that composes LINQ
chains over `IQueryable<Product>` and hands them to the adapter. The TypeScript
side implements the adapter against `bun:sqlite`, reading the captured
descriptor list off each query and translating it into a single parameterized
SQL statement.

## What this sample exercises

- **`[Transpile]` interfaces (`IProductRepository`)** — emitted as TypeScript
  interfaces that a hand-written class implements.
- **`[Import]` for runtime modules (`Database`, `Statement`)** — Bun's built-in
  `bun:sqlite` is bound through C# façades; method bodies throw on the .NET
  side because the real implementation lives in JS.
- **`[Emit]` extension methods (`Statement.All`, `Statement.Run`, `Statement.Get`)** —
  variadic `params object?[]` arguments lower to JS rest spread (`stmt.all(...args)`)
  via raw-template emission.
- **`IQueryable<T>` lowering** — the receiver triggers Phase B capture, so every
  `Where` / `OrderBy` / `Take` lambda body lands in the runtime descriptor's
  `queryable.tree` slot alongside the closure.
- **`getStages` runtime helper** — the repository reads the descriptor list off
  the materialized result without monkey-patching `linq()` or relying on test-only
  capture helpers.
- **Mapping camelCase ↔ snake_case** — entity properties live in camelCase
  (`displayName`, `unitPrice`); SQLite columns live in snake_case
  (`display_name`, `unit_price`); the repository carries an explicit
  `productColumn` map so `ExprMember.member` resolves to the right column.
- **Decimal interop** — `Product.UnitPrice` is `decimal` on the C# side; values
  flow as `decimal.js` instances in TS and the translator collapses them to
  REAL via `toNumber()` when binding parameters.

## Assumptions and prerequisites

1. **Phase B capture is enabled.** `IQueryable<T>` chains automatically opt into
   tree capture — the receiver type triggers
   `IrExpressionExtractor.ShouldCaptureExpressionTree`. Plain `IEnumerable<T>`
   chains do not, and the SQL translator would never run.
2. **Runtime exposes `LINQ_STAGES` / `getStages`.** These were added in #200; the
   repository falls back to the closure path when they are missing.
3. **Bun runtime.** `bun:sqlite` is shipped with Bun by default. Tests run under
   `bun test`; the sample is not portable to Node without swapping the adapter.
4. **MVP translator scope.** The repository handles `Where`, `Select` (single
   member projection), `OrderBy{,Descending}`, `ThenBy{,Descending}`, `Take`,
   `Skip`, plus `Count` / `First` / `FirstOrDefault` terminals. Anything outside
   that subset throws `UntranslatableTreeError` and the repository falls back
   to running the chain via the runtime closure path.

├── Product.cs              # transpiled record (positional ctor)
├── Js/BunSqlite/
│   ├── Database.cs         # [Import("Database", "bun:sqlite")]
│   └── Statement.cs        # [External] interface + [Emit] extensions
└── Provider/

    └── ProductDemo.cs          # [Transpile] static demo entry points
```

```
targets/js/sample-queryable-sqlite/
├── src/                    # Generated by Metano (NOT edited by hand)
│   ├── product.ts
│   ├── provider/
│   │   ├── i-product-repository.ts
│   │   ├── product-demo.ts
│   │   └── … (hand-written companions live here too)
│   └── index.ts

The C# project sets `MetanoClean=false` so the hand-written TS providers under
`src/provider/` survive between regenerations. Resource / asset copy from the
C# project is tracked separately in #199.

## Running

```sh
# Regenerate TS from the C# domain + adapter contract.
dotnet build samples/SampleQueryableSqlite/

# Build + test the TS side.
cd targets/js/sample-queryable-sqlite
bun install
bun run build
bun test
```

## What's intentionally NOT in this sample

- No SQL `JOIN` / `GroupBy` / aggregate translators. The descriptor union covers
  them, but the SQL emission for those is sample-specific work.
- No connection pool / transaction story. `bun:sqlite` is opened in-memory per
  test run.
- No reflection-based mapping. The column map is hand-authored, mirroring how
  EF Core's `OnModelCreating` behaves but simpler.
- No generic ORM library. The repository is concrete to `Product` for clarity;
  generalizing to any entity is the natural next step (and aligns with the
  visitor API tracked in #198).
