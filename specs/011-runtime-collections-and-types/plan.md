# Implementation Plan: BCL collections as runtime types, runtime type descriptors

**Branch**: `spec/011-runtime-collections-and-types` | **Date**: 2026-11-01 | **Spec**: [spec.md](./spec.md) | **Issue**: [#335](https://github.com/danfma/metano/issues/335)

## Summary

Metano 3.0.0 makes the BCL collections `metano-runtime` classes (D1), introduces `JsArray<T>` for the native array (D2), makes BCL exceptions runtime classes with a typed-catch lowering (D10), replaces IIFEs with methods and helpers (D4), and adds runtime type descriptors consumed by `is` / `as` / patterns / `catch` / `GetType()` / `typeof` / JSON (D5–D9, D14). Three interop features complete it: `dynamic` as `any` (D11), `Js.Code` inline target code (D12), and the `UnsafeCast<T>()` / `AsDynamic()` escape hatches (D13). Every emission shape and runtime module is tree-shakable and measured in CI (D17). It ships in one major with #328, spec 009 and spec 010 (D16). The maintainer's decisions of 2026-11-16 ship every collection of the spec in 3.0.0 (D24, which superseded the first-day narrowing D20: stage 011c delivers `List`, `HashSet`, `Dictionary`, `Queue` and `Stack`, stage 011h the read-only, immutable, sorted and concurrent classes), make every array crossing an explicit C# conversion (`ToArray()` copies; `AsJsArray()` / `AsSpan()` / `AsReadOnlySpan()` are zero-copy views over the list's single backing array; D21, D27), replace the ratio gate by an absolute per-operation overhead budget measured on Node.js and Bun in the hot-helper shape (D25, research R17), and let a bundle-time constant drop the bounds checks and version tracking in production (D26, FR-058).

## Benchmark plan (NFR-001; not run in this PR)

- **Harness**: `targets/js/metano-runtime/bench/collections.bench.ts`, run with `bun run bench` (Bun) and `bun run bench:node` (the same file under Node.js); both scripts added in 011c. **Both engines are the gate** (NFR-001, D25): Node.js at the LTS line `ci.yml` pins (24 today) and Bun; each run records the engine versions and the machine. The harness follows research R17: one generated module per case run in a **fresh process**, 10 untimed warm-up runs, 21 timed runs, the median, every result written to a sink.
- **Shape** (the gate's): **hot helper**: each case is a kernel that makes one pass over a 1e4-element collection (1e4 integers, short strings, record instances `Point(x, y)` with `equals` / `hashCode`, or reference-keyed instances) and is called 500 times, so 5e6 operations per measurement run in regular (non-OSR) optimized code. The spike's long single loop (1e6 elements, 5 passes, inside one call) is run as a diagnostic only, because V8 executes it as on-stack-replacement code, where any branch costs about 4× (research R17).
- **Cases** (each vs its native baseline): `List.get` sequential and data-driven vs `a[i]`; `List.set` vs `a[i] = v`; `list[i] += 1` in FR-010's emitted form vs `a[i] += 1`; `get` at a polymorphic site (four element types); `List.add` vs `push`; the lowered `foreach` over `List` vs `for..of` over an array (and `[Symbol.iterator]`, reported); `Dictionary` / `ConcurrentDictionary` `get` / `set` / `containsKey` / `add` with number and string keys vs `Map`; `HashSet` `add` / `contains` / `remove` vs `Set` (and vs 2.x's `HashSet`, reported); `Queue` / `Stack` vs a native array; record-keyed and reference-keyed `Dictionary` / `HashSet`, the sorted classes at 1e3 / 1e4 / 1e5 elements and the immutable classes (absolute times, reported); LINQ `where` + `select` + `toList` over `List` vs over array (reported).
- **Method**: every process also runs the **calibration kernel** (a native-array `a[i] = a[i] + 1` loop in the same shape); the gating figure is the normalized overhead per operation, `(median − baseline median) / operations × C_ref / C_measured`, with C_ref = 0.59 ns (Node) / 0.47 ns (Bun) from the reference machine of research R17 (Apple M1 Pro, Node.js 24.11, Bun 1.4.2). The measurement uses the **default build** (no `define`; FR-058's checks on). `docs/runtime-types.md` records the raw and normalized tables, C_measured, the engine versions and the machine for every release.
- **Gate**: every normalized budget of NFR-001 on both engines (the larger counts); a miss blocks the stage until the design is revisited (OD-3 / OD-4 are the levers) or the maintainer records a budget change. Research R17 measured the chosen storage (`defineProperty` + unsigned compare) at 0.45 / 0.74 / 0.82 / 0.86 ns on Node (sequential get, data-driven get, set, read-modify-write) and 0.27 / 0.25 / 0.41 / 0.63 ns on Bun.
- **The design that satisfies NFR-001** (not normative beyond FR-002 / FR-057; research R17 holds the measurements): storage in non-enumerable own data properties defined through `defineProperty` in the constructor, always `_items`, `_version`, `$typeArguments$List` in that order (one hidden class; `adopt` goes through the constructor); `get` / `set` test `(index >>> 0) >= this._items.length` and call a cold module-level `throwOOR(index)`; enumeration failures go through a cold exported `throwModified()`; no `#private` (Node `Add` 1.9× slower), symbol keys (same penalty), closures (13–26× on Node), generators (8–28×) or `Proxy` (70–500×); no inline bounds check at the call site (no consistent gain, needs right-hand-side temporaries); the lazy version (`_version++` only while an enumerator is live) is not adopted (it narrows but does not close the write gap and needs every enumerator path to decrement reliably).
- **Size** (NFR-008): the FR-043 suite's numbers are copied into the same table.

## Tree-shaking suite (FR-043; from 011a on)

- `targets/js/metano-runtime/test/tree-shaking/size-budgets.json`: one entry per NFR-008 row (`{ "entry": "entries/list-only.ts", "maxGzip": 2560, "mustNotContain": ["Dictionary", "HashSet", "Temporal"] }`), plus one entry per runtime module for the side-effect-only suite.
- `bundle.test.ts`: for each entry, `Bun.build({ entrypoints, minify: true, target: "browser", format: "esm" })` and `esbuild.build({ bundle: true, minify: true, format: "esm" })`; `Bun.gzipSync` on each output; assert `byteLength <= maxGzip` for the larger of the two and `!output.includes(s)` for every `mustNotContain`.
- `side-effects.test.ts`: for each module, copy the built `dist/<module>.js` (and the runtime modules it imports) into a temporary directory that contains **its own `package.json` without a `sideEffects` field** (bundlers read the nearest `package.json` upward, so a bare directory under `/tmp` inherits any stray parent `sideEffects: false`; research R13), mark every third-party package external (`external: ["@js-temporal/polyfill", …]`), bundle `import "./<module>.js";` with Rollup (`@rollup/plugin-node-resolve`, `@rollup/plugin-terser`) and assert the output has 0 bytes of that module's code (an empty module or `export {}` only); the same with bun and esbuild. A variant of the suite that resolves the real package through `node_modules` MUST force `moduleSideEffects: true` in a `resolveId` hook (`return { id, moduleSideEffects: true }`), because node-resolve honours `sideEffects: false` even under `treeshake.moduleSideEffects: true`. The **canary** (normative, FR-043): a fixture module `canary.js` whose only content is `register();` goes through the identical pipeline and MUST produce non-zero bytes containing `register`; the suite fails before any real module is checked if the canary is dropped. Entry-point modules of a sample are asserted as kept.
- `tests/Metano.Tests/TreeShaking/ExpectedOutputBundleTests.cs`: for every `Expected/*.ts`, compiles it with **tsgo** (`--module esnext --target es2022`, imports of generated siblings and of `metano-runtime` resolved to stubs that export the referenced names), bundles the compiled module as a side-effect-only import (`import "./golden.js"`) with every package external through the same non-trusting configuration as `side-effects.test.ts` (a temp dir with its own `package.json`, the canary first), and asserts that **nothing but the external `import` statements remains** — the rule is "no code evaluated at module load", which a text scanner cannot implement (it would flag the prescribed `test: (v) => implementsInterface(...)` literal and miss unannotated initializers). Goldens of `[ModuleEntryPoint]` sources are exempt (listed by the test from the attribute in their C# source). `tests/Metano.Tests/TreeShaking/allowlist.txt` (feeds this golden bundle check only) names the #361 goldens `branded-value-object.ts` and `nested-types-static-class.ts`; the runtime side-effect suite has its own `targets/js/metano-runtime/test/tree-shaking/allowlist.json` naming `system/uuid` and `system/collections/immutable-collection` (until 011h). Each test fails if a listed entry no longer violates (stale) or if an unlisted one violates, so both lists only shrink; a second assertion fails the build while either list is non-empty and the version being released is 3.0.0.
- `targets/js/sample-runtime-types/test/tree-shaking/`: the same two bun suites over the regenerated sample with its own budgets (the factory scenario entry must not contain the surviving literal `"Geometry.Blob"`; the "no questions" entry must not contain the `castTo` message literal `"Unable to cast object"` and is byte-compared per NFR-010 — a minified bundle has no module paths, so `mustNotContain` never lists one; the entry-point module is kept under a side-effect-only import).
- CI: both bun suites and the golden bundle check run in `ci.yml` on every PR and in `release.yml` before `semantic-release`.

## Test strategy

- **Core units**: `CollectionKindResolver` for every C# type of FR-001 (source and metadata symbols, variance); `IrRuntimeTypeTest.Of` for every category with and without a static type (`ArrayTuple` and `Constant` included); `RuntimeTypeReachability` (class receiver reaches derived types; `object` / `Exception` / interface / `T` receivers per FR-027; interfaces force `plainImplementers`; JSON reaches; downcasts reach; questioned collection kinds; consumer implementers of a library interface; nothing else does); `ReifiedTypeParameterAnalysis` (each trigger, non-triggers such as `new List<T>()` / `default(T)` / `x.GetType()`, implementation-group propagation, overload independence, statics, derived classes, MS0054 positions including the referenced-package case, trailing / defaulted / before-`params` placement); `PlainObjectOverlapAnalysis` (covers / covered / mutual / none); the inline-code string-literal lexer.
- **Goldens**: listed per stage above, each checked by `tsgo --strict` in the sample where applicable and by the golden bundle check.
- **Diagnostics**: one test per reason of contracts/diagnostics.md (MS0045 4 reasons, MS0046 2, MS0047 1, MS0048 2, MS0049 3, MS0050 1, MS0051 3, MS0052 2, MS0053 4, MS0054 2, MS0055 3, MS0056 1 with three literal kinds, MS0057 1, MS0058 2), asserting code, severity and location; warning tests also assert emission.
- **Runtime (bun)**: every member of contracts/runtime-collections.md including exceptions and messages, enumeration-invalidation rules per class (including the `Dictionary.remove` exemption), `defaultEquals` / `defaultHashCode` (record keys, reference keys, `NaN`), `adopt` sharing and fixed-size throws, `toArray` detachment and the `List` views' identity across mutations plus the length check of the enumerator (FR-055–FR-057, SC-009), `asArray`, the wildcard rule, covariant interface tests; `toJSON` per class; every `getRuntimeType` fallback including `Object.hasOwn` on a derived class without a getter; every descriptor `test`; `asType` / `castTo` / `withImplementers`; memoization identity; `toException` for `Exception`, `Error`, `AbortError` `DOMException`, string, `undefined`; `tryFilter`; `copyRecordWith` with `$typeArguments$<Class>`; the typed-catch chain through generated code.
- **End-to-end**: regenerated samples build and pass; the new `sample-runtime-types` runs US3 / US4 / US6 / US8 scenarios; spec 009's conformance sample is byte-identical; the spec 007 smoke test covers the new subpaths and the bundler step.
- **NFR-002 / NFR-010**: the pinned `NoRuntimeQuestions` fixture (records, methods, a string enum; no collections, exceptions or numeric enums) is transpiled before 011b and after 011d and the diff is empty; `SampleTodo` is transpiled the same way and every hunk is matched against the NFR-010 allowed shapes; both bundles contain no `system/reflection` byte.
- **Dart**: FR-038 items in each stage, deferred to after 3.0.0 (D28); until then each stage asserts the existing Dart output is byte-identical.
- **Regression**: the full TUnit suite and every bun sample.

## CI changes

- `ci.yml`: `cd targets/js/metano-runtime && bun test test/tree-shaking`; `cd targets/js/sample-runtime-types && bun run build && bun test` (includes its tree-shaking suite); the golden bundle check runs with the normal test command; `bun run bench --check` is **not** in CI (benchmarks are a review artifact, run on demand and recorded); the smoke test of spec 007 gains the three subpaths and the bundler step; the `git diff --exit-code targets/` check covers the regenerated samples (TS and Flutter).

## Compatibility and migration

See spec.md § Migration (3.0.0). Consumers without runtime-type questions see only the collection / exception / enum migration (NFR-002). Cross-package consumers must upgrade both sides. The incremental cache's `ConfigurationFingerprint` gains a `runtime-types-v1` token so 2.x caches never mask the new output (as ADR-0025 did for the layout).

## Risks

| ID | Risk | Mitigation |
|---|---|---|
| K1 | `List.get(i)` / `set` are slower than `arr[i]` in hot loops | Accepted by the maintainer (D25): NFR-001 budgets the absolute overhead (about 1 ns per `get` / `set`), measured in the hot-helper shape on both engines; research R17's design meets it; the long-loop ratio (the spike's 4.7×) was an on-stack-replacement artefact. FR-058 lets a production bundle drop the checks. |
| K2 | JS consumers of generated packages break on `List` where they expected arrays, some silently at run time (`items[0]`, `toHaveLength`, `structuredClone`, `<For each>`; research R16) | 3.0.0 major; migration notes (D23); `Iterable` + `toJSON` + `toArray()` copies + the `List` views (FR-055, FR-056) + `adopt`; `JsArray<T>` for interop signatures; no implicit conversion hides a copy. |
| K3 | Reachability misses a type (a `GetType()` answer or `is IFoo` falls back wrongly) | The receiver rules of FR-027 are unit-tested; OD-6 (a) makes library descriptors complete; the fallback answers by `constructor.name`. |
| K4 | Hidden parameters change public TS signatures | Only bodies that ask get them (FR-024); MS0050 names every interop-visible one; `UnknownType` is the wildcard. |
| K5 | `dynamic` extraction paths are unexplored (research R6 [I]) | Stage 011e starts with a probe matrix over every `IDynamic*Operation` before any lowering is written. |
| K6 | Typed catch now rethrows what 2.x swallowed | Called out first in the migration notes; the chain is pinned by goldens. |
| K7 | The `[PlainObject]` overlap relation (009 FR-019) is conservative and warns on legitimate shapes | It is a warning; `UnsafeCast` or a `[JsonPolymorphic]` discriminator are the documented ways out. |
| K8 | Spec 009 / 010 follow-up edits drift from this spec | The interaction table is the checklist for those PRs; the union path is exercised by 011b's goldens. |
| K9 | A bundler version changes what it keeps (research R13 measured specific versions) | FR-043 re-measures on every PR with pinned dev-dependency versions; a regression fails the PR, not the release. |
| K10 | A descriptor regresses to a factory call, or a `/*#__PURE__*/` annotation on a memoized-factory call is lost by a formatter step | Descriptors are literals, so no annotation is needed for them; the `one exception ≤ 0.5 KB` budget, the `mustNotContain` entries over surviving literals (`"Unable to cast object"`, a descriptor `fullName`) and NFR-010's byte comparison catch a regression; where an annotation is still used, the printer emits it as part of the node, not as comment trivia that Biome may move. |
| K12 | The side-effect-only suite becomes vacuous again (a bundler setting or a stray parent `package.json` trusts `sideEffects`) | The canary is normative (FR-043): the suite bundles a fixture with a top-level `register()` call first and asserts it is kept; the temp dir ships its own `package.json`; third-party packages are external. |
| K14 | The strict-guard module reintroduces an ESM cycle through a different edge (a variant that imports the guard) | The golden's Bun test imports the base first unbundled; the import collector forbids a variant → guard import (a variant tests itself with its own `isX`, never with `isBase`). |
| K13 | #361 slips and the allowlist is still non-empty at release time | The release gate (FR-040, SC-008) fails `release.yml` while the list is non-empty; the maintainer decides between landing #361 and holding 3.0.0, never shipping with the lie. |
| K11 | The lazy getter's module-level `let` collides with a user identifier | The `$rt` suffix follows the naming policy's reserved `$` prefix rule (no C# identifier emits a `$`). |
