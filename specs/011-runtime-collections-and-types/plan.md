# Implementation Plan: BCL collections as runtime types, runtime type descriptors

**Branch**: `spec/011-runtime-collections-and-types` | **Date**: 2026-11-01 | **Spec**: [spec.md](./spec.md) | **Issue**: [#335](https://github.com/danfma/metano/issues/335)

## Summary

Metano 3.0.0 makes the BCL collections `metano-runtime` classes (D1), introduces `JsArray<T>` for the native array (D2), makes BCL exceptions runtime classes with a typed-catch lowering (D10), replaces IIFEs with methods and helpers (D4), and adds runtime type descriptors consumed by `is` / `as` / patterns / `catch` / `GetType()` / `typeof` / JSON (D5–D9, D14). Three interop features complete it: `dynamic` as `any` (D11), `Js.Code` inline target code (D12), and the `UnsafeCast<T>()` / `AsDynamic()` escape hatches (D13). Every emission shape and runtime module is tree-shakable and measured in CI (D17). It ships in one major with #328, spec 009 and spec 010 (D16).

## Technical Context

- **Language/Version**: C# 14 on .NET 10 for the compiler (SDK 11 RC once spec 010's toolchain stage lands); TypeScript (runtime, generated code) built with `tsgo`; Bun for tests, the benchmark and the bundle checks.

## Benchmark plan (NFR-001; not run in this PR)

- **Harness**: `targets/js/metano-runtime/bench/collections.bench.ts`, `mitata`, run with `bun run bench` (script added in 011c); Node 22 is run once for comparison, Bun is the gate.
- **Fixtures**: 1e6 integers, 1e5 short strings, 1e5 record instances (`Point(x, y)` with `equals` / `hashCode`), 1e5 instances of a class without `equals` (reference keys).
- **Cases** (each vs its native baseline): `List.get` / `set` in a `for` loop vs `arr[i]`; `List.add` vs `push`; `for..of` over `List` (with the version check) vs array; `Dictionary.get` / `set` / `containsKey` with number and string keys vs `Map`; `Dictionary` with record keys (no native baseline: reported absolute, with `Map`-by-reference as the lower bound) and with reference keys; `HashSet.contains` 3.0 vs 2.x; `Queue.dequeue` ring buffer vs `shift`; `Stack.pop` vs `pop`; LINQ `where` + `select` + `toList` over `List` vs over array.
- **Method**: median of 10 runs after 3 warm-up runs, GC between cases; the ratio to the baseline is the reported figure; `docs/runtime-types.md` records the table and the machine.
- **Gate**: every budget of NFR-001; a miss blocks 011c until OD-3 / OD-4 are revisited.
- **Size** (NFR-008): the FR-043 suite's numbers are copied into the same table.

## Tree-shaking suite (FR-043; from 011a on)

- `targets/js/metano-runtime/test/tree-shaking/size-budgets.json`: one entry per NFR-008 row (`{ "entry": "entries/list-only.ts", "maxGzip": 2560, "mustNotContain": ["Dictionary", "HashSet", "Temporal"] }`), plus one entry per runtime module for the side-effect-only suite.
- `bundle.test.ts`: for each entry, `Bun.build({ entrypoints, minify: true, target: "browser", format: "esm" })` and `esbuild.build({ bundle: true, minify: true, format: "esm" })`; `Bun.gzipSync` on each output; assert `byteLength <= maxGzip` for the larger of the two and `!output.includes(s)` for every `mustNotContain`.
- `side-effects.test.ts`: for each module, copy the built `dist/<module>.js` (and what it imports) into a temporary directory **outside any package that declares `sideEffects`** (no `package.json` on the path: a local file is side-effectful by default), bundle `import "./<module>.js";` with Rollup (`@rollup/plugin-node-resolve`, `@rollup/plugin-terser`) and assert the output has 0 bytes of that module's code (an empty module or `export {}` only); the same with bun and esbuild. A variant of the suite that resolves the real package through `node_modules` MUST force `moduleSideEffects: true` in a `resolveId` hook (`return { id, moduleSideEffects: true }`), because node-resolve honours `sideEffects: false` even under `treeshake.moduleSideEffects: true` (research R13); the suite's own self-test asserts that a fixture module with a top-level `register()` call is **kept** (non-zero bytes), so the check can never be vacuous again. Entry-point modules of a sample are asserted as kept.
- `tests/Metano.Tests/TreeShaking/ExpectedOutputSideEffectScanTests.cs`: parses every `Expected/*.ts` with a small line-level scanner (no TS compiler dependency) and fails on: **a call in a top-level statement or initializer that is not immediately preceded by `/*#__PURE__*/`**; `export namespace` whose body has a non-type member; `export enum`; `static [` / `[Symbol.` other than `[Symbol.iterator]` inside a class body. Goldens of `[ModuleEntryPoint]` sources are exempt (listed by the test from the attribute in their C# source). `allowlist.txt` names the #361 shapes (`branded-value-object.ts`, `nested-types-static-class.ts`); the test fails if a listed file no longer violates (stale entry) or if an unlisted file violates, so the list only shrinks; a second assertion fails the build while the list is non-empty and the version being released is 3.0.0.
- `targets/js/sample-runtime-types/test/tree-shaking/`: the same two bun suites over the regenerated sample with its own budgets (the factory scenario entry must not contain `Blob`; the "no questions" entry must not contain `system/reflection` identifiers; the entry-point module is kept under a side-effect-only import).
- CI: both bun suites and the TUnit scan run in `ci.yml` on every PR and in `release.yml` before `semantic-release`.

## Test strategy

- **Core units**: `CollectionKindResolver` for every C# type of FR-001 (source and metadata symbols, variance); `IrRuntimeTypeTest.Of` for every category with and without a static type (`ArrayTuple` and `Constant` included); `RuntimeTypeReachability` (class receiver reaches derived types; `object` / `Exception` / interface / `T` receivers per FR-027; interfaces force `plainImplementers`; JSON reaches; downcasts reach; questioned collection kinds; consumer implementers of a library interface; nothing else does); `ReifiedTypeParameterAnalysis` (each trigger, non-triggers such as `new List<T>()` / `default(T)` / `x.GetType()`, implementation-group propagation, overload independence, statics, derived classes, MS0054 positions including the referenced-package case, trailing / defaulted / before-`params` placement); `PlainObjectOverlapAnalysis` (covers / covered / mutual / none); the inline-code string-literal lexer.
- **Goldens**: listed per stage above, each checked by `tsgo --strict` in the sample where applicable and by the side-effect scan.
- **Diagnostics**: one test per reason of contracts/diagnostics.md (MS0045 4 reasons, MS0046 2, MS0047 1, MS0048 2, MS0049 3, MS0050 1, MS0051 3, MS0052 2, MS0053 4, MS0054 2, MS0055 3, MS0056 1 with three literal kinds), asserting code, severity and location; warning tests also assert emission.
- **Runtime (bun)**: every member of contracts/runtime-collections.md including exceptions and messages, enumeration-invalidation rules per class (including the `Dictionary.remove` exemption), `defaultEquals` / `defaultHashCode` (record keys, reference keys, `NaN`), `adopt` sharing and fixed-size throws, `asArray`, the wildcard rule, covariant interface tests; `toJSON` per class; every `getType` fallback including `Object.hasOwn` on a derived class without a getter; every descriptor `test`; `asType` / `castTo` / `withImplementers`; memoization identity; `toException` for `Exception`, `Error`, `AbortError` `DOMException`, string, `undefined`; `tryFilter`; `copyRecordWith` with `$typeArguments$<Class>`; the typed-catch chain through generated code.
- **End-to-end**: regenerated samples build and pass; the new `sample-runtime-types` runs US3 / US4 / US6 / US8 scenarios; spec 009's conformance sample is byte-identical; the spec 007 smoke test covers the new subpaths and the bundler step.
- **NFR-002 / NFR-010**: the pinned `NoRuntimeQuestions` fixture (records, methods, a string enum; no collections, exceptions or numeric enums) is transpiled before 011b and after 011d and the diff is empty; `SampleTodo` is transpiled the same way and every hunk is matched against the NFR-010 allowed shapes; both bundles contain no `system/reflection` byte.
- **Dart**: FR-038 items in each stage.
- **Regression**: the full TUnit suite and every bun sample.

## Compatibility and migration

See spec.md § Migration (3.0.0). Consumers without runtime-type questions see only the collection / exception / enum migration (NFR-002). Cross-package consumers must upgrade both sides. The incremental cache's `ConfigurationFingerprint` gains a `runtime-types-v1` token so 2.x caches never mask the new output (as ADR-0025 did for the layout).

## Risks

| ID | Risk | Mitigation |
|---|---|---|
| K1 | `List.get(i)` is measurably slower than `arr[i]` in hot loops | NFR-001 budgets gate 011c; OD-3 / OD-4 are the levers; V8 inlines monomorphic methods (assumption, verified by the benchmark). |
| K2 | JS consumers of generated packages break on `List` where they expected arrays | 3.0.0 major; migration notes; `Iterable` + `toJSON` + `toArray()` / `adopt` conversions; `JsArray<T>` for interop signatures. |
| K3 | Reachability misses a type (a `GetType()` answer or `is IFoo` falls back wrongly) | The receiver rules of FR-027 are unit-tested; OD-6 (a) makes library descriptors complete; the fallback answers by `constructor.name`. |
| K4 | Hidden parameters change public TS signatures | Only bodies that ask get them (FR-024); MS0050 names every interop-visible one; `UnknownType` is the wildcard. |
| K5 | `dynamic` extraction paths are unexplored (research R6 [I]) | Stage 011e starts with a probe matrix over every `IDynamic*Operation` before any lowering is written. |
| K6 | Typed catch now rethrows what 2.x swallowed | Called out first in the migration notes; the chain is pinned by goldens. |
| K7 | The `[PlainObject]` overlap relation (009 FR-019) is conservative and warns on legitimate shapes | It is a warning; `UnsafeCast` or a `[JsonPolymorphic]` discriminator are the documented ways out. |
| K8 | Spec 009 / 010 follow-up edits drift from this spec | The interaction table is the checklist for those PRs; the union path is exercised by 011b's goldens. |
| K9 | A bundler version changes what it keeps (research R13 measured specific versions) | FR-043 re-measures on every PR with pinned dev-dependency versions; a regression fails the PR, not the release. |
| K10 | A descriptor regresses to a factory call, or a `/*#__PURE__*/` annotation on a memoized-factory call is lost by a formatter step | Descriptors are literals, so no annotation is needed for them; the `one exception ≤ 0.5 KB` budget and the `mustNotContain: ["system/reflection"]` entries catch a regression; where an annotation is still used, the printer emits it as part of the node, not as comment trivia that Biome may move. |
| K12 | The side-effect-only suite becomes vacuous again (a bundler setting trusts `sideEffects`) | The suite's self-test bundles a fixture with a top-level `register()` call and asserts it is kept; the fixture is part of the suite, so a vacuous configuration fails on it first. |
| K13 | #361 slips and the allowlist is still non-empty at release time | The release gate (FR-040, SC-008) fails `release.yml` while the list is non-empty; the maintainer decides between landing #361 and holding 3.0.0, never shipping with the lie. |
| K11 | The lazy getter's module-level `let` collides with a user identifier | The `$rt` suffix follows the naming policy's reserved `$` prefix rule (no C# identifier emits a `$`). |
