# Feature Support Matrix (Baseline)

What Metano supports **today**, with code + test traceability. Per
[../contracts/baseline-matrix.contract.md](../contracts/baseline-matrix.contract.md). Migrated from
`old-spec/08-feature-support-matrix.md` and extended with `Code area` + `Test` columns (every
`Implemented` row resolves to real code + a real test — SC-001).

Status legend: **Implemented** = part of the current product · **Partial** = supported with explicit
constraints · **Planned** = not a current guarantee. Unless a row names a backend, it describes the
**TypeScript** backend (the normative reference surface). Paths are repo-relative.

| Expressions | Collection expressions `[]` | TS | Implemented | `Extraction/IrExpressionExtractor.cs`, `IR/IrExpression.cs` | `tests/Metano.Tests/CollectionInitTests.cs` | — |
| Expressions | Index-from-end `x[^n]` and ranges `x[a..b]` | TS / Dart | Partial | `Extraction/IrExpressionExtractor.IndexAndRange.cs`, `IR/IrExpression.cs` (IrSliceExpression) | `tests/Metano.Tests/IndexAndRangeTests.cs` | FR-014. Arrays, strings, `List<T>`/`IList<T>`/`IReadOnlyList<T>` (ranges: arrays, strings, `List<T>`). `^n` → `x[x.length - n]` (keeps the indexer's element type under `tsc --strict`, unlike `at()`); ranges → `slice` (Dart: `sublist`/`substring`). | Expressions | Integer division `/`, `/=` | TS / Dart | Partial | `Extraction/IrExpressionExtractor.IntegerDivision.cs`, `IR/IrExpression.cs` (`IrBinaryOp.IntegerDivide`), `Bridge/IrToTsExpressionBridge.cs`, `targets/js/metano-runtime/src/system/integer-division.ts` | `tests/Metano.Tests/IntegerDivisionTranspileTests.cs`, `targets/js/metano-runtime/test/system/integer-division.test.ts` | FR-014. | Statements | `for` loops and multi-declarator locals | TS | Implemented | `Extraction/IrStatementExtractor.cs`, `IR/IrStatement.cs` (IrForStatement), `Bridge/IrToTsStatementBridge.cs` | `tests/Metano.Tests/ForLoopTranspileTests.cs` | FR-014. Loops and `try` print as raw text that carries its mapped nodes, so a type or runtime helper used only inside one is still imported. | Expressions | Null-conditional access `a?.b`, `a?[i]` | TS / Dart | Partial | `Extraction/IrExpressionExtractor.cs` (`LowerConditionalContinuation`), `IR/IrExpression.cs` (IrNullConditionalAccess), `Bridge/IrToTsExpressionBridge.NullConditional.cs` | `tests/Metano.Tests/NullConditionalMappingTranspileTests.cs` | Every step after `?.` keeps its own lowering (BCL mappings, extensions, `[Emit]`, `[Inline]`, LINQ, index-from-end); the receiver is evaluated once. TS keeps native `?.` for plain steps and guards the receiver otherwise; Dart prints native null-shorting for plain member/element chains and binds and guards the receiver otherwise (`(($receiver) => $receiver == null ? null : step($receiver))(a)`). A native TS chain yields `undefined` for a null receiver, so one read as a value (returned, stored, passed, an object-literal value, an equality between two chains) is normalized to `?? null`; it stays bare as the left operand of `??`, beside `== null` or another literal, as a receiver, and when discarded (#256). |
| Expressions | Lifted operators over nullable values, `Nullable<T>` members | TS / Dart | Partial | `Extraction/IrExpressionExtractor.LiftedOperators.cs`, `Extraction/IrExpressionExtractor.NullableValueMembers.cs` | `tests/Metano.Tests/LiftedNullableOperatorTests.cs` | FR-014, FR-005. Lifted arithmetic/bitwise/shift and unary operators yield `null` for a null operand (`x == null ? null : x + 1`), relational ones `false` (`x != null && x < 5`); a null-conditional operand moves the operator into its guard (`o?.Items.Count + 1` → `o == null ? null : o.items.length + 1`); side-effecting operands are evaluated once, in source order. String `+`, `+=` and interpolation holes format a maybe-null operand as `""`. `HasValue` → `x != null`, `Value` → `x` when nullable analysis proves it non-null and `x ?? throw InvalidOperationException` otherwise, `GetValueOrDefault()` → `x ?? default(T)`. Nullable array elements print as `(T \| null)[]`. `GetValueOrDefault()` on a type-parameter `T?` reports MS0001. Limitations: equality keeps `===` (#256 covers `undefined` chains; `decimal?` equality compares references), `bool?` `&`/`\|`/`^` keep the unlifted lowering, `++`/`--` and compound assignment to a target with side effects are not lifted, format and alignment clauses are dropped. Dart promotes only locals, so a guard over a property operand (`o.qty == null ? null : o.qty + k`) relies on the guard closure's untyped (`dynamic`) parameter or does not type-check, and the unproven-`Value` throw names the BCL `InvalidOperationException`, which the Dart backend does not map yet. |
| Expressions | Unsupported expression constructs | TS / Dart | Implemented | `Extraction/IrExpressionExtractor.cs` (`ReportUnsupported`), `Bridge/IrToTsExpressionBridge.cs` | `tests/Metano.Tests/IndexAndRangeTests.cs` | FR-038. Reported as MS0001 at the expression; the output gets a placeholder that parses anywhere and throws when reached, so one construct never aborts the build. |
