# Feature Support Matrix (Baseline)

What Metano supports **today**, with code + test traceability. Per
[../contracts/baseline-matrix.contract.md](../contracts/baseline-matrix.contract.md). Migrated from
`old-spec/08-feature-support-matrix.md` and extended with `Code area` + `Test` columns (every
`Implemented` row resolves to real code + a real test — SC-001).

Status legend: **Implemented** = part of the current product · **Partial** = supported with explicit
constraints · **Planned** = not a current guarantee. Unless a row names a backend, it describes the
**TypeScript** backend (the normative reference surface). Paths are repo-relative.

| Expressions | Null-conditional access `a?.b`, `a?[i]` | TS / Dart | Partial | `Extraction/IrExpressionExtractor.cs` (`LowerConditionalContinuation`), `IR/IrExpression.cs` (IrNullConditionalAccess), `Bridge/IrToTsExpressionBridge.NullConditional.cs` | `tests/Metano.Tests/NullConditionalMappingTranspileTests.cs` | Every step after `?.` keeps its own lowering (BCL mappings, extensions, `[Emit]`, `[Inline]`, LINQ, index-from-end); the receiver is evaluated once. A native TS chain yields `undefined` for a null receiver, so one read as a value (returned, stored, passed, an object-literal value, an equality between two chains) is normalized to `?? null`; it stays bare as the left operand of `??`, beside `== null` or another literal, as a receiver, and when discarded (#256). |
| Expressions | Lifted operators over nullable values, `Nullable<T>` members | TS / Dart | Partial | `Extraction/IrExpressionExtractor.LiftedOperators.cs`, `Extraction/IrExpressionExtractor.NullableValueMembers.cs` | `tests/Metano.Tests/LiftedNullableOperatorTests.cs` | FR-014, FR-005. Dart promotes only locals, so a guard over a property operand (`o.qty == null ? null : o.qty + k`) relies on the guard closure's untyped (`dynamic`) parameter or does not type-check, and the unproven-`Value` throw names the BCL `InvalidOperationException`, which the Dart backend does not map yet. |
